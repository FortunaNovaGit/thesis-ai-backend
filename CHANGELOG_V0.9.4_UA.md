# Thesis AI v0.9.4 — Quality-First Elementor Storefront

**Дата:** 4 листопада 2026. **Базова версія:** v0.9.3. **Тип:** staging-реліз, НЕ фінальний production release.

## Чому створено v0.9.4

Фактичні скриншоти EasyWP показали вузьку (~770 px) смугу замість повноширинної сторінки, дубльований заголовок «Головна», слабку типографіку, пусті псевдофотографії товарів, надумані назви карток, багатослівний беззмістовний текст. Основний pipeline v0.9.3 міг завершитися «успішно», але не гарантував прийнятну візуальну якість.

## Змінено в backend

- `app/agents/runtime.py`: підтверджені товари витягуються з явного списку назв; спеціальна секція підтверджених назв має пріоритет над довільними цитатами з промпту. Кнопки, заголовки й заклики не стають WooCommerce-товарами. **Жодних анонімних «Демо-товар 01» без підтвердженої назви**.
- `app/component_library.py`: без верифікованого фото Hero залишається типографічним; прибрано величезню порожню псевдофотографію. Секція товарів без підтверджених позицій не демонструє вигаданий каталог. Підтверджені назви без фото відображаються компактними редакційними текстовими рядами замість прямокутників `01/02`.
- `app/component_library.py`: для головної сторінки зображення, обране власником через WordPress Media Library, має пріоритет над нечітким зіставленням текстів. URL і ID перевіряються; зовнішня довільна URL-адреса не використовується.
- `app/content_quality.py`, `app/creative_pipeline.py`, `app/agents/prompts.py`: мала відтворювана перевірка беззмістовних фраз, виявлених у реальному контенті; Creative Director отримує вимогу писати корисний конкретний текст, а не «спокійний вибір без зайвих обіцянок».
- `qa/visual_audit.py`: крім DOM-помилок, фіксує `narrow_ai_canvas`, `duplicate_theme_page_title`, `large_decorative_placeholder`, `offscreen_ai_section`. Працює з фактичним staging URL і локальними тестовими файлами; **не виконується автоматично під час WordPress Build**.
- `qa/v094_breakout_smoke.py`: локальний Chromium-сценарій, який навмисно задає вузьку рамку теми 770 px і перевіряє повноширинні секції на 1440/900/390/320 px.

## Змінено у WordPress Bridge

- Для AI-owned Elementor-документів примусово задано `hide_title=yes`, `page_layout=elementor_full_width`, а після збереження повторно підтверджується `_wp_page_template=elementor_full_width`. Інші сторінки не змінюються.
- Scoped CSS: повноширинні секції використовують 100vw breakout із центруванням у межах вузької теми; контент секцій лишається обмеженим читабельною максимальною шириною. Заголовок WordPress теми прихований лише на AI-owned сторінках.
- В адмін-брифі додано **точні назви демотоварів** (макс. 4), окремо від **майбутньої кількості товарів**, із санітизацією.
- В адмін-брифі додано **WordPress Media Picker** для головного Hero-зображення, з мініатюрою та можливістю прибрати вибір. У збереженому стані міститься лише ID вкладення, який перевіряється повторно.
- Preflight повідомляє кількість доступних локальних зображень і попереджає, якщо медіабібліотека порожня.
- ZIP WordPress Bridge містить лише `thesis-ai-bridge/` — без копії backend.

## Відомі обмеження

1. **Media Pipeline v1** використовує лише наявні власні зображення з WordPress Media Library; автоматичну генерацію AI-зображень, ліцензування та upload потоку ще НЕ реалізовано.
2. Існуючий WooCommerce Shop Archive не перетворюється на повністю редаговану в Elementor Free сторінку. Головна/Контакти та інші AI-драфти — редаговані Elementor V3-контейнери; каталог керується WooCommerce.
3. Немає end-to-end підтвердження на живому EasyWP саме з v0.9.4; нову збірку потрібно тестувати на staging.
4. Visual Critic із AI-аналізом скриншотів та автоматичний delta-repair НЕ реалізовано. CLI Playwright — інструмент для ручної локальної перевірки.
5. Гарна верстка не гарантує професійний дизайн: потрібні бренд-факти, якісні власні медіа, перевірка конкретного контенту.

## Перевірки до релізу

- `python -m pytest -q` — Python regression suite (без OpenAI API).
- `php -d zend.assertions=1 -d assert.exception=1 plugin/thesis-ai-bridge/tests/brief_smoke.php`.
- `php -l` всіх 5 PHP файлів.
- `node --check plugin/thesis-ai-bridge/assets/admin.js`.
- `python qa/v094_breakout_smoke.py` — Chromium responsive smoke на 1440/900/390/320 з навмисно вузьким контейнером теми.
- `python qa/visual_audit.py --url file:///.../synthetic-staging.html --allow-local-fixture --output ...` — Playwright report.
- Після пакування — розпакування обох ZIP і повторний запуск тестів, `php -l`, `node --check`.

**Не було витрачено токенів OpenAI на локальні тести.**
