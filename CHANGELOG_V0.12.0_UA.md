# Thesis AI v0.12.0 — Rich Visual System (staging release)

**Дата:** 18 листопада 2026 року. **База:** Backend + Bridge v0.11.0.
**Статус:** локально перевірена збірка (тести + синтетичні скриншоти). Живий EasyWP/Elementor E2E **не виконувався**.

## Чому сайти виглядали «сухо» (діагноз)

На синтетичному рендері v0.11 Fortuna Nova (`evidence/before-*.png`) видно корінь проблеми — це **компілятор**, а не лише тексти AI:

1. Кожна секція компілювалась однаково: «маленький заголовок + абзац + сітка однакових плашок». Креативні параметри AI (`card_presentation`, `heading_emphasis`) майже не змінювали структуру.
2. `items` у Hero ігнорувались, не було другої дії, іконок, декоративної геометрії → порожній перший екран.
3. Bento-картка при 3 пунктах ставала величезним порожнім прямокутником.
4. Розміри шрифтів фіксовані (34 px H2, 17 px текст) — без масштабу і контрасту.
5. Модные латинські шрифти (Poppins, DM Sans, Fraunces, Syne) **не мають кирилиці** → браузер підставляв системний шрифт.
6. FAQ, процес, CTA, товари — усі виглядали як однакові картки.

## Що зроблено

### Backend (`app/component_library.py` — нові рендерери)
- **Hero**: eyebrow-«пігулка», великий H1 з акцентним курсивом останніх слів, основна + **друга (контурна) дія**, рядок **highlight-пунктів з іконками** з `items` (службові/порожні пункти відфільтровуються наявним content gate). З фото — пункти йдуть смугою під композицією.
- **Іконки**: нативний Elementor Icon (Font Awesome 5 Free, вбудований в Elementor Free). Вибір детермінований за ключовими словами, тільки з allowlist; LLM назви іконок не задає.
- **Презентації карток** тепер змінюють структуру:
  - `bento` — головна картка в основному кольорі з орнаментом + 2–3 допоміжні;
  - `list` — редакційні рядки з великими курсивними номерами;
  - `timeline` (нове) — кроки, з'єднані лінією; на mobile — вертикальна шкала;
  - `grid` — рівні картки з іконками й hover-підйомом.
  - Процес автоматично стає `timeline`, якщо AI вибрав grid/bento.
- **Нова секція `statement`** — один великий типографічний «маніфест» між щільними блоками.
- **FAQ** — розділений макет (вступ + список) на нативних `<details>`: доступно з клавіатури, без JS, кожна відповідь — окремий редагований Text Editor.
- **CTA** — фінальна смуга з великим заголовком і декоративними кільцями.
- **Товари без фото** — чесні текстові картки з абстрактним CSS-орнаментом (не фальшиве фото товару).
- **Ритм фону**: якщо AI поставив 3+ однакові світлі секції поспіль, компілятор чергує default/soft (темні/акцентні вибори AI не змінюються).
- **Якорі секцій** (`#products`, `#process`, `#faq`…) — друга дія може вести на реальну секцію.
- **Нативна адаптивна типографіка**: розміри для desktop/tablet/mobile через стандартні Elementor-контроли.

### Backend (схеми, агенти)
- `CreativeSection`/`SectionContentSpec`: `secondary_cta_label`, `secondary_cta_url` (перевіряються `safe_cta_url`, не можуть дублювати основну дію); `kind=statement`; `card_presentation=timeline`. Старі артефакти сумісні (поля мають default).
- `design_safety.cyrillic_safe_fonts()` — **guard кириличних шрифтів** у `CreativeFoundation`: латинські-only шрифти замінюються близькими за стилем (serif → Cormorant Garamond / Lora, display → Unbounded, sans → Manrope).
- Промпт Creative Director: розділ «VISUAL RICHNESS» — як і коли використовувати нові інструменти, короткі заголовки, чергування фонів, кириличні шрифти.
- `/health` → `version: 0.12.0`, `features.rich_sections: rich_visual_system_v1`, `cyrillic_font_guard: true`.

### WordPress Bridge 0.12.0
- Новий `assets/rich-sections.css` (статичний, рецензований CSS; **кожен селектор** починається з `body.thesis-ai-generated` і стосується лише секцій `.tai-rich`, тобто сторінки старих версій виглядають як раніше).
  Токени кольорів похідні від дизайн-системи через `color-mix()`: лінії, тінти, світіння, тіні.
  Анімації: м'яка поява Hero (CSS), scroll-reveal через `animation-timeline: view()` **лише як прогресивне покращення** — без підтримки контент просто видно; `prefers-reduced-motion` вимикає все.
- Санітайзер Elementor приймає: `_css_classes`, `_element_id` (лише `[a-z0-9-]`), `typography_font_size_tablet/_mobile`, `typography_letter_spacing`, `typography_font_style` (`normal|italic`), `align_mobile`. Allowlist віджетів **не розширювався**.
- Дизайн-токени `--tai-heading-font`, `--tai-body-font`.

- Старі синтетичні смоуки (`layout_smoke`, `generative_layout_smoke`, `v091_primitives_smoke`, `visual_composer_smoke` 20/20, `v094_breakout_smoke`) — PASS.
- Новий `qa/rich_preview.py`: Fortuna Nova Home (7 секцій) × 2 креативні напрями × з фото/без × 1440/390 — без горизонтального переповнення, 1 H1, без JS-помилок. Емулює CSS, який Elementor генерує з налаштувань віджетів (з тією ж специфічністю), але **це не живий Elementor**.
- `qa/visual_audit.py` тепер знімає живі скриншоти з `reduced_motion=reduce`, щоб scroll-анімації не давали «порожніх» нижніх блоків.

## Обмеження та що перевірити на staging
- Не перевірено в живому Elementor: відображення Font Awesome іконок, `<details>` після `wp_kses_post` (очікується, що WP дозволяє `details/summary`), `_element_id` як якір, адаптивні розміри.
- Великі заголовки/H2 мають `!important` clamp-розміри в CSS (як і v0.8–v0.11): зміна розміру шрифту H1/H2 у панелі Elementor не перекриє стиль. Інші тексти редагуються штатно.
- Bridge 0.11 + Backend 0.12: нові ключі тихо відкидаються, сайт будується, але без нового вигляду. Оновлюйте **обидва**.
- Якість текстів, як і раніше, залежить від LLM; компілятор не вигадує фактів, тільки оформлює.
- Mock-режим (`AGENT_MODE=mock`) не використовує нові можливості (statement/secondary CTA) — їх задає лише реальний Creative Director.
