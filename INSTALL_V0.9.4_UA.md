# Як встановити Thesis AI / AI Website Builder v0.9.4

v0.9.4 — staging release для перевірки візуальної якості. Він не змінює загальний п'ятиагентний WordPress Pull-процес, Render/PostgreSQL або правила безпечного виконання.

## 0. Перед оновленням

1. Створи backup **тестового WordPress** і завантаж ZIP поточного плагіна.
2. Збережи копію поточного GitHub backend. Запиши, який commit зараз працює на Render.
3. **Не видаляй** Elementor, WooCommerce, товари чи інші власні сторінки. Для заміни Bridge вибирай `Replace current with uploaded`.
4. `DATABASE_URL`, `BACKEND_TOKEN_SECRET`, `BACKEND_PAIRING_SECRET` не змінюй. Не завантажуй секрети в GitHub.

## 1. Backend у GitHub + Render

1. Розпакуй `thesis-ai-backend-v0.9.4.zip` у локальну копію вже наявного backend репозиторію (без створення нового repo). **Залишити існуючі секрети тільки в Render Environment**.
2. Перед push перевір `git diff` і переконайся, що налаштування Render/твої приватні конфігурації не загублені.
3. Зроби commit і push у налаштовану Render гілку. Переконайся, що Render Deploy завершився успішно.
4. Відкрий `https://<твій-render-backend>/health`. Перевір `version: "0.9.4"`, а також реальний `agent_mode` і відсутність помилок у Render logs.

## 2. Онови WordPress Bridge

1. WordPress → Plugins → Add Plugin → Upload Plugin.
2. Обери **лише** `thesis-ai-bridge-v0.9.4.zip`.
3. Натисни **Replace current with uploaded**. **Не обирай Delete/Uninstall**, щоб не втратити конфігурацію.
4. Очисть кеш сайту та CDN. Переконайся, що у списку плагінів версія **0.9.4**.
5. AI Website Builder → перевір Backend connection → **Preflight**. Виведи кількість фото та перевір, що Elementor активний.

## 3. Підготуй матеріали до build — це важливо для дизайну

Тепер один промпт все ще достатній для прототипу, але **для якісного магазину варто використати бриф**:

- Бренд: `Fortuna Nova`.
- Тип сайту: `інтернет-магазин шоколадних цукерок ручної роботи`.
- Сторінки: `Головна, Магазин, Контакти`.
- Кількість товарів: **планова кількість**, наприклад `24` — це не створення 24 вигаданих товарів.
- Реальні назви демотоварів: **по одному на рядок**, наприклад `Асорті 16 цукерок` та `Асорті 24 цукерки`. Плагін створює тільки WooCommerce **Draft**, без вигаданих цін/складу/залишків. Максимум 4 назви за один тест.
- Власні зображення: спочатку завантаж у WordPress → Media → Add New. Для головного Hero натисни «Обрати фото» в брифі, вибери якісне власне зображення. Для товарних фото заповни title/alt так, щоб назва й кількість відповідали товару (наприклад, `Асорті 16 цукерок`).
- Візуальний стиль та HEX-кольори можна залишити порожніми, якщо хочеш дати Creative Director свободу.
- Не вводь вигадані факти, адреси, сертифікати, склади або ціни.

### Контрольний промпт

> Створи професійний сучасний сайт-магазин Fortuna Nova українською. Рівно три сторінки: Головна, Магазин, Контакти. Створи виразну оригінальну композицію для преміального шоколадного бренду, з акцентом на типографіку, фотографії з наявної WordPress Media Library, чітку історію бренду та логічний шлях до перегляду каталогу. Уникай повторів, абстрактних обіцянок і штучного тексту. Головна повинна мати один H1, сильний Hero, товарні колекції (лише з підтверджених назв) і змістовний CTA. Магазин — використовуй WooCommerce Shop як системну сторінку, не перезаписуй її. Контакти — форма без вигаданих реквізитів. Додай SEO, адаптивність та редагованість в Elementor Free. Нічого не публікуй автоматично.

## 4. Перевір після Build

1. Відкрий створену **Draft** Home через preview адміністратора. Якщо бачиш старі стилі — очисть cache/CDN, перевір активну версію Bridge та CSS URL.
2. На desktop 1440 px секції мають заповнювати ширину viewport, а **текст залишатися в читабельній зоні**, не у вузькій 770 px смузі. `Головна` не має з'являтися окремим другим заголовком над Hero.
3. У товарному блоці не має бути псевдотовару «Обрати цукерки», а без фото не повинно бути великих нумерованих заглушок.
4. У Elementor відкрий одну AI-owned сторінку і переконайся, що Hero, заголовки, тексти, кнопка й зображення — окремі редаговані віджети.
5. Перевір 390 px mobile, CTA, меню, контактну форму. Магазин `/shop/` керується WooCommerce, а не Elementor Free Theme Builder.
6. Перевір WooCommerce Products: лише підтверджені товари зі статусом **Draft**, без вигаданих цін і stock.

## 5. Опціональна Playwright-перевірка реального preview

У директорії backend локально на комп'ютері (на staging, не на production) встанови `pip install playwright` і `python -m playwright install chromium`, якщо браузера ще немає. Для **доступного без авторизації** staging URL:

```bash
python qa/visual_audit.py --url 'https://staging.example/my-page/' --output qa/evidence-home
```

Для приватного Preview потрібен заздалегідь створений локальний Playwright `storage_state` авторизованої сесії, передавати пароль чи cookies у чат або Render не потрібно. Інструмент збере скриншоти для 1440, 900, 390 і 320 px та перевірить DOM, ширину секцій, другий заголовок теми, пусті псевдомедіаблоки. Він **не використовує OpenAI API**. Позитивний DOM report **не доводить wow-дизайн**, його потрібно переглянути візуально.

## 6. Коли зупинитися

Якщо бачиш `NameError`, Content Quality Gate, PHP critical error, JS error або навіть повторну вузьку верстку — **не витрачай ще один платний Build**. Збери точний лог Render і WordPress статус, screenshot/URL preview та познач, на якому кроці зупинилося виконання. Не чіпай реальні WooCommerce товари або чужі сторінки.

### Обмеження v0.9.4

Це ще **не** автономний готовий генератор професійних магазинів: немає генерації й ліцензійної перевірки нових AI-фото, інтегрованого Visual Critic/delta-repair і повного Elementor Free WooCommerce archive editor. v0.9.4 прибирає конкретні помилки з реальних скриншотів, додає керування медіа та готовність до суворішого staging QA.
